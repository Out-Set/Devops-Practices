# How to run Java services on HTTPS?

There are a few common ways to do this, depending on your setup.

## Option 1: Configure HTTPS directly in your Java app

### For Spring Boot
1. **Generate a keystore** (self-signed for dev, or use a real cert for prod):
```bash
keytool -genkeypair -alias myapp -keyalg RSA -keysize 2048 \
  -storetype PKCS12 -keystore keystore.p12 -validity 3650
```

2. **Add to `application.properties`**:
```properties
server.port=8443
server.ssl.key-store=classpath:keystore.p12
server.ssl.key-store-password=yourpassword
server.ssl.key-store-type=PKCS12
server.ssl.key-alias=myapp
```

That's it — Spring Boot's embedded Tomcat/Netty will serve HTTPS on port 8443.

### For plain Java (no framework) — `HttpsServer`
```java
HttpsServer server = HttpsServer.create(new InetSocketAddress(8443), 0);
SSLContext sslContext = SSLContext.getInstance("TLS");

KeyStore ks = KeyStore.getInstance("PKCS12");
ks.load(new FileInputStream("keystore.p12"), "yourpassword".toCharArray());

KeyManagerFactory kmf = KeyManagerFactory.getInstance("SunX509");
kmf.init(ks, "yourpassword".toCharArray());

sslContext.init(kmf.getKeyManagers(), null, null);
server.setHttpsConfigurator(new HttpsConfigurator(sslContext));
server.createContext("/", exchange -> { /* handler */ });
server.start();
```

### For Tomcat (standalone), configure `server.xml`:
```xml
<Connector port="8443" protocol="org.apache.coyote.http11.Http11NioProtocol"
           maxThreads="150" SSLEnabled="true">
    <SSLHostConfig>
        <Certificate certificateKeystoreFile="conf/keystore.p12"
                     certificateKeystorePassword="yourpassword"
                     type="RSA" />
    </SSLHostConfig>
</Connector>
```

## Option 2: Terminate HTTPS at a reverse proxy (most common in production)

Run your Java service over plain HTTP internally, and let **nginx**, **Apache**, **Caddy**, or a cloud load balancer handle TLS termination. This is generally preferred because:
- Certificate renewal (e.g. via Let's Encrypt) is decoupled from your app
- You avoid re-deploying the app to rotate certs
- Load balancers/proxies are optimized for TLS handling

Example nginx config:
```nginx
server {
    listen 443 ssl;
    server_name myapp.com;

    ssl_certificate     /etc/letsencrypt/live/myapp.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/myapp.com/privkey.pem;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## Which should you use?

- **Direct HTTPS in the app**: good for internal services, microservices with mTLS, or when you don't have a proxy layer.
- **Reverse proxy termination**: best practice for public-facing production services — easier cert management (especially with Let's Encrypt/Certbot auto-renewal).
